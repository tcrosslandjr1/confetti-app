# Confetti AI Learning Engine — Architecture Spec

## Overview

The AI Learning Engine is the data backbone that connects user behavior (searches, saves, plans, feedback) to the Taste Agent and Recommendation Agent. Every interaction teaches Confetti something new — about the user AND about venues.

---

## 1. Tracking Number System

Every plan generated by Confetti gets a unique **Boarding Pass Tracking ID**.

### Format

```
CONF-{5-digit alphanumeric}
```

Examples: `CONF-48271`, `CONF-A3F92`, `CONF-73916`

### Generation Rules

- Generated at plan creation time (server-side, not client)
- Unique across all users and all plans globally
- Stored in `plans` table as `tracking_id` (indexed, unique constraint)
- Displayed on the boarding pass UI in JetBrains Mono with a live pulse dot (teal)
- Used as the primary reference ID when users share, rate, or revisit plans

### Data Model — `plans` Table Extension

```sql
ALTER TABLE plans ADD COLUMN tracking_id VARCHAR(10) UNIQUE NOT NULL
  DEFAULT 'CONF-' || LPAD(FLOOR(RANDOM() * 100000)::TEXT, 5, '0');

CREATE INDEX idx_plans_tracking_id ON plans(tracking_id);
```

### What the Tracking Number Unlocks

| Signal | Source | Feeds Into |
|--------|--------|-----------|
| Plan completed | User follows full itinerary | Taste Agent Layer 2 (Behavioral) |
| Plan abandoned at stop N | User drops off mid-plan | Recommendation Agent (venue quality scoring) |
| Plan shared | User sends to friends | Social virality score for venue |
| Plan rated | 1-5 star post-night rating | Taste Agent + Venue quality index |
| Plan re-used | Another user steals this plan | Plan template ranking |

## 2. Restaurant Search Index

### How Search Works

1. User types a query (e.g., "sushi", "rooftop bar", "Rasika")
2. Client sends query to `/api/search/venues` endpoint
3. Backend searches the `venues` table (full-text + fuzzy match)
4. Results returned with venue cards
5. **Every search is logged** to `search_events` table

### Data Model — `search_events` Table

```sql
CREATE TABLE search_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES auth.users(id),
  query TEXT NOT NULL,
  results_count INT,
  result_venue_ids UUID[],
  clicked_venue_id UUID,
  saved_venue_id UUID,
  inferred_cuisine TEXT[],
  inferred_vibe TEXT[],
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_search_events_user ON search_events(user_id, created_at DESC);
CREATE INDEX idx_search_events_query ON search_events USING gin(to_tsvector('english', query));
```

### Venue Database — `venues` Table

```sql
CREATE TABLE venues (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  cuisine TEXT,
  neighborhood TEXT,
  city TEXT NOT NULL,
  price_tier TEXT CHECK (price_tier IN ('$', '$$', '$$$', '$$$$')),
  vibe_tags TEXT[],
  lat DECIMAL(10, 7),
  lng DECIMAL(10, 7),
  avg_rating DECIMAL(3, 2),
  total_plans_featured INT DEFAULT 0,
  total_searches INT DEFAULT 0,
  total_saves INT DEFAULT 0,
  is_sponsored BOOLEAN DEFAULT FALSE,
  source TEXT, -- 'google_places', 'yelp', 'manual', 'user_submitted'
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_venues_city ON venues(city);
CREATE INDEX idx_venues_search ON venues USING gin(
  to_tsvector('english', name || ' ' || COALESCE(cuisine, '') || ' ' || COALESCE(neighborhood, ''))
);
```

## 3. AI Learning Pipeline

### 3.1 Signal Collection

Every user action generates a signal:

| Action | Signal Type | Weight | Destination |
|--------|------------|--------|------------|
| Search query | `search` | 1x | Taste Agent Layer 2 |
| Click on result | `click` | 2x | Taste Agent Layer 2 |
| Save venue to favorites | `save` | 3x | Taste Agent Layer 1 + 2 |
| Add venue to plan | `plan_add` | 4x | Taste Agent Layer 2 |
| Complete a plan stop | `visit` | 5x | Taste Agent Layer 2 |
| Rate a venue | `rate` | 5x | Taste Agent Layer 1 |
| Skip a search result | `skip` | -1x | Taste Agent Layer 2 (negative signal) |
| Share a plan | `share` | 3x | Social Graph Layer 3 |

### 3.2 Taste Graph Update Flow

```
User Action
    ↓
Signal Collector (Edge Function)
    ↓
┌─────────────────────────────┐
│   User Taste Graph (DB)     │
│                             │
│  cuisine_affinities: {}     │
│  vibe_affinities: {}        │
│  price_preference: {}       │
│  neighborhood_affinity: {}  │
│  time_preference: {}        │
│  group_size_history: []     │
│  occasion_patterns: {}      │
│  search_history: []         │
│  venue_interactions: []     │
│  confidence_score: 0-100    │
└─────────────────────────────┘
    ↓
Taste Agent reads graph at plan-generation time
    ↓
Recommendation Agent receives taste profile
    ↓
Personalized plan with unique tracking ID
```

### 3.3 Venue Learning (How the AI Discovers New Places)

When users search for a venue that **doesn't exist** in the Confetti database:

1. Log the search miss to `search_misses` table
2. If the same venue name is searched 3+ times by different users → flag for auto-import
3. Background job calls Google Places API to pull venue details
4. New venue added to `venues` table with `source: 'user_discovered'`
5. The discovering users get a "You found a hidden gem" notification

```sql
CREATE TABLE search_misses (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  query TEXT NOT NULL,
  user_id UUID REFERENCES auth.users(id),
  city TEXT,
  hit_count INT DEFAULT 1,
  auto_imported BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

This creates a **user-powered venue discovery loop** — the more people search, the smarter the database gets.

## 4. Integration with Existing Agents

### Taste Agent Updates

Add to Layer 2 (Behavioral Layer) inputs:

```
NEW SIGNALS FROM LEARNING ENGINE:
- search_history: Array of {query, timestamp, results_clicked}
- cuisine_affinity_scores: Object mapping cuisine → confidence (0-1)
- vibe_affinity_scores: Object mapping vibe → confidence (0-1)
- price_preference_distribution: {$: %, $$: %, $$$: %, $$$$: %}
- venue_interaction_log: Array of {venue_id, action_type, timestamp}
- discovery_contributions: Count of venues the user helped discover
```

### Recommendation Agent Updates

Add to venue selection logic:

```
NEW INPUTS FROM LEARNING ENGINE:
- user_taste_profile: Full taste graph summary from Taste Agent
- tracking_id: Assigned to every generated plan
- venue_popularity_scores: Based on aggregate search/save/visit data
- venue_freshness: How recently the venue was added or verified
- venue_user_match_score: How well this venue matches THIS user's graph
```

### Group Taste Graph Updates

When merging taste profiles for Party Room:

```
NEW MERGE INPUTS:
- Per-member search history overlap (shared cuisine interests)
- Per-member venue save overlap (venues multiple members saved)
- Combined price tolerance range
- Group vibe consensus from individual vibe_affinities
```

## 5. Privacy & Data

- All taste data is tied to `user_id` and never shared with other users
- Users can view their taste profile in Settings → "My Taste DNA"
- Users can reset their taste graph at any time
- Search history older than 90 days is aggregated (query removed, only affinity scores kept)
- Venue-level aggregates (total searches, total saves) are anonymized

## 6. API Endpoints

```
POST   /api/search/venues          — Search venues, log search event
GET    /api/search/suggestions      — AI-powered suggestions based on taste graph
POST   /api/venues/save             — Save a venue, update taste graph
GET    /api/taste/profile            — Get current user's taste profile
DELETE /api/taste/reset              — Reset taste graph
GET    /api/plans/:tracking_id       — Look up plan by tracking number
POST   /api/plans/:tracking_id/rate  — Rate a completed plan
GET    /api/discover/trending        — Trending venues from aggregate search data
```

## 7. Supabase Edge Function — Signal Collector

```typescript
// supabase/functions/signal-collector/index.ts

import { serve } from 'https://deno.land/std@0.168.0/http/server.ts'
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'

serve(async (req) => {
  const { user_id, signal_type, payload } = await req.json()

  const supabase = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!
  )

  // 1. Log raw signal
  await supabase.from('user_signals').insert({
    user_id,
    signal_type, // 'search', 'click', 'save', 'plan_add', 'visit', 'rate'
    payload,
    created_at: new Date().toISOString()
  })

  // 2. Update taste graph
  const { data: graph } = await supabase
    .from('user_taste_graphs')
    .select('*')
    .eq('user_id', user_id)
    .single()

  if (graph) {
    const updated = updateTasteGraph(graph, signal_type, payload)
    await supabase
      .from('user_taste_graphs')
      .update(updated)
      .eq('user_id', user_id)
  }

  // 3. Update venue stats if applicable
  if (payload.venue_id) {
    await supabase.rpc('increment_venue_stat', {
      p_venue_id: payload.venue_id,
      p_stat: signal_type === 'search' ? 'total_searches'
            : signal_type === 'save' ? 'total_saves'
            : 'total_plans_featured'
    })
  }

  return new Response(JSON.stringify({ ok: true }), {
    headers: { 'Content-Type': 'application/json' }
  })
})
```
