🔴 Critical — Blocks core usage

Users cannot complete essential tasks or get trapped in dead-end screens.

Active pass has no back button or navigation Critical
Page: Active Pass Detail (Boarding Pass view)
The active pass detail view (accessed from TONIGHT section or Your Trips) has no back arrow, no close button, and no bottom navigation bar. Users are completely trapped — the only escape is browser back, which exits the entire app to the root URL and resets the session.
Fix: Add a back arrow in the top-left corner and restore the bottom navigation bar. Implement proper in-app routing so browser back stays within the app.
Browser back exits entire app Critical
Page: Any detail view → browser back
Pressing the browser back button from any detail view (active pass, settings, about, etc.) navigates to the root URL "/" instead of the previous in-app screen. The app resets completely — user must re-enter through onboarding/login. This is because the app doesn't use proper history management for internal navigation.
Fix: Implement pushState/replaceState history management or use TanStack Router's history API so in-app navigation creates proper history entries. Browser back should return to the previous in-app screen.
Explore/Feed — nearly invisible UI elements Critical
Page: Explore / Feed (TikTok-style venue swipe)
The coral/salmon background on venue cards makes multiple critical UI elements nearly invisible: the back arrow (dark on coral), the three-dot menu (dark on coral), filter chips at the top, and the venue description text. Users cannot see how to navigate back or access filters.
Fix: Add a dark semi-transparent gradient overlay at the top of the card for the back arrow and menu. Use white or high-contrast text/icons over the coral background. Give filter chips a solid background with sufficient contrast.
Settings gear icon non-functional Critical
Page: Profile → gear icon (top right)
The settings gear icon on the Profile page does not respond to clicks. Tested twice across sessions — no action occurs. Users can only reach Settings through the MORE section on the dashboard, which is not discoverable.
Fix: Wire up the gear icon's onClick handler to navigate to the Settings page.
App resets to onboarding on every fresh load Critical
Page: App entry / confetti-live.html
Navigating directly to confetti-live.html always shows the onboarding flow (Step 1) even for returning users. There is no session persistence — if the browser back bug ejects the user or they refresh, they must click through all 5 onboarding steps plus the intro carousel to return to their dashboard.
Fix: Persist onboarding completion state (localStorage or auth token). If the user has completed onboarding, skip directly to dashboard or login screen.
🟠 High — Significant UX friction

Navigation gaps, missing controls, and visibility issues that degrade the experience.

Bottom nav missing on 8+ pages High
Pages: Crews, Command Center (all 6 tabs), Sparkle Chat, About, Settings, For Venues, Promoters, Events, Active Pass, Your Trips
The bottom navigation bar disappears on the majority of detail and sub-pages. Users lose their primary navigation method and must rely on back arrows (when present) to return to the dashboard. Some pages have neither back buttons NOR bottom nav, creating dead ends.
Fix: Show the bottom nav bar consistently on all pages except full-screen modals (like Add a Place). At minimum, ensure every page without bottom nav has a visible back button.
Sparkle chat send button — low contrast High
Page: Sparkle AI Chat
The send arrow button in the Sparkle chat input area is a light gray arrow on a cream/off-white background. It's nearly invisible and doesn't look interactive. Users may not realize how to send their message.
Fix: Use the coral/salmon brand color for the send button, or place it inside a solid circle background. Ensure WCAG AA contrast ratio (4.5:1) against the input background.
Active pass timeline dots not interactive High
Page: Active Pass (in-progress boarding pass)
The numbered timeline dots (1, 2, 3) on the active pass look like tappable navigation elements but do not respond to clicks. Users expect to tap a stop number to jump to that stop's details, but nothing happens.
Fix: Either make the dots tappable to jump between stops, or change the visual treatment so they don't look like buttons (remove the circular affordance).
Settings back nav goes to Profile, not dashboard High
Page: Settings → back arrow
The back arrow on Settings navigates to the Profile page instead of the dashboard. Since Settings is accessed from the dashboard MORE section (not from Profile), this is disorienting. Combined with no bottom nav on Settings, users must tap back again from Profile and then use the home tab.
Fix: Back button should return to the previous screen (use navigation stack), or at minimum go to the dashboard since Settings is accessed from MORE.
Onboarding step number mismatch High
Page: Onboarding Step 5
The last onboarding step shows the label "STEP 04" but the progress bar reads "5/5". This creates confusion about whether there are 4 or 5 steps. The numbering is inconsistent.
Fix: Update the label to "STEP 05" to match the progress bar, or re-number steps consistently.
Pass detail view has no back button High
Page: "Your night, printed." (pass detail from Your Trips)
The full pass detail view ("Your night, printed.") has no back arrow, close button, or bottom navigation. Users viewing a past or planned pass have no way to return to the trips list or dashboard without browser back (which exits the app).
Fix: Add a back arrow in the top-left area next to the confetti logo. This page already has a header area with space for navigation.
No responsive layout — app locked in phone frame High
Page: All pages
The entire app renders inside a fixed-width phone mockup frame at every viewport size. On desktop browsers, the content area is a narrow centered column surrounded by a large dark background. The app has zero responsive behavior — mobile and desktop views are identical pixel-for-pixel. Desktop users get a phone-sized experience.
Fix: For the prototype/demo, this is acceptable. For production, consider removing the phone frame on mobile devices (where it's redundant) and potentially offering a wider layout on tablet/desktop.
🟡 Medium — Design inconsistencies

Confusing patterns, unclear affordances, and content issues.

Day type filters reorder but don't filter Medium
Page: Dashboard — "WHAT KIND OF DAY?" buttons
The day type buttons (go out, stay in, host, recharge) reorder the category sections on the dashboard but don't actually filter or hide irrelevant categories. Selecting "stay in" still shows outdoor-focused categories like "Active" — they just move lower. Users expect filtering behavior from filter-styled buttons.
Fix: Either hide irrelevant categories when a filter is selected, or change the visual language to indicate these are "sort by priority" controls, not filters.
All plan cards route to Sparkle chat — no plan detail Medium
Page: Dashboard — all plan type cards (museum + lunch, gallery hop, etc.)
Every plan type card on the dashboard navigates to the same Sparkle AI chat interface regardless of which plan was tapped. There are no plan-specific detail pages showing what's included, example itineraries, or pricing. Users don't get any preview before committing to a chat conversation.
Fix: Consider adding a brief plan detail overlay or bottom sheet that shows what the plan type includes before launching into Sparkle chat. At minimum, pre-fill the Sparkle chat with context about the selected plan type.
Kids tab shows identical content to Family tab Medium
Page: Dashboard — Kids audience tab
The Kids tab appears to show the exact same category sections and plan types as the Family tab. If these are intended to be different audiences, the content should differ. If they share content, consider merging them to reduce confusion.
Fix: Differentiate Kids content (age-appropriate activities, kid-focused venues) or merge Kids into Family as a sub-filter.
Promoters "HOW IT WORKS" label — low contrast Medium
Page: Be a Promoter
The "HOW IT WORKS" section label appears in light gray text on the dark background. It doesn't stand out as a section header and could be easily missed.
Fix: Use the cream/off-white color for section headers on dark backgrounds to maintain hierarchy and readability.
Command Center tab bar requires horizontal scroll Medium
Page: Command Center
The Command Center has 6 sub-tabs (saved spots, people, prefs, host templates, upcoming, vibe profile) but only 4 are visible. "Upcoming" and "vibe profile" are hidden off-screen with no scroll indicator. Users may not discover these tabs exist.
Fix: Add a subtle scroll fade or arrow indicator on the right side of the tab bar to signal more tabs exist. Or reorganize into a 2-row grid if all tabs are equally important.
Scrapbook cards lack tap affordance Medium
Page: Dashboard — YOUR SCRAPBOOK section
The scrapbook cards (Bushwick crawl, Date night LES, Solo culture) look like decorative summary cards rather than tappable elements. There's no arrow, chevron, or "view" indicator to signal they lead to the full trip list page.
Fix: Add a subtle chevron or "view all →" link to indicate these cards are interactive.
🟢 Low — Polish items

Minor visual inconsistencies and refinement opportunities.

Intro carousel "next →" button style inconsistency Low
Page: Intro Carousel (3-step)
The intro carousel uses a dark/black "next →" button, while all onboarding steps use the coral/salmon CTA button. This creates a visual inconsistency in the first-run experience.
Fix: Standardize button style — use coral for all primary CTAs throughout the onboarding flow.
Events page capacity bars lack labels Low
Page: Events ("What's on.")
Event cards show colored fill bars (32%-94% full) but there's no label explaining what the bar represents. Users may not understand these indicate remaining capacity.
Fix: Add a "capacity" or "% full" label near the bars, or use a tooltip on tap.
Your Trips — Draft card uses diagonal stripes Low
Page: Your Trips list
The draft trip card ("Crew night out") uses a diagonal stripe pattern that looks like a rendering artifact or broken texture rather than a deliberate "draft" visual treatment. It doesn't match the clean visual language of the other cards.
Fix: Use a more intentional draft indicator — a dashed border, a "DRAFT" badge, or a muted/desaturated version of the card color.
"+add a place" button appears in multiple contexts Low
Pages: Dashboard MORE section, Your Trips, Social section cards
The "+add a place" button appears in the dashboard MORE grid, inside the Social section card grid, and in the Your Trips list — all with the same label but potentially different purposes. In the Social section it occupies a plan card slot, which is confusing.
Fix: Differentiate the actions (e.g., "suggest a venue" vs "add a stop to this trip") or consolidate to one entry point.
Audit Methodology
This audit was conducted by navigating every reachable page and interactive element in the Confetti app at ai-lifestyle-concierge.vercel.app/confetti-live.html. Screenshots were captured at both desktop (1568×745) and mobile (375×812) viewport widths. The app renders inside a fixed-width phone mockup frame, so content is identical at both sizes — no responsive layout differences were found.
